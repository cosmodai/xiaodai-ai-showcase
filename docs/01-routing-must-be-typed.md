# 复盘 01：路由信号必须走类型化参数

*[English](en/01-routing-must-be-typed.md)*

## 现象

主脑需要把任务交给某个子 agent。早期的做法是让它在回复里写出路由标记，再由程序解析。运行一段时间后出现两个问题：

1. 主脑有时只“说”要转交，却没有真正调用工具。对话越长，这种情况越频繁。
2. 我们想用 PreToolUse hook 拦截不合规的路由，却发现有些路由根本没经过 hook。

## 根因

两个问题指向同一件事：**文本和工具调用走的是两条不同的通道。**

- PreToolUse hook 只能看到工具调用。模型输出的普通文本走的是另一条出口，hook 从架构上就拦不到。
- 路由规则每轮都注入到上下文里，随着对话变长不断累积，模型越来越倾向于“用叙述代替行动”：描述自己要做什么，而不是去做。

## 修法

把路由从文本挪进工具参数：

- 新增一个调度工具，路由目标是 `Literal` 枚举参数，只能取固定的几个值。
- PreToolUse hook 校验这个参数，非法值直接拒绝。
- 路由规则在系统提示里写一次，不再每轮注入。
- 加一条检查：如果某一轮主脑表达了转交意图却没有调度调用，视为派单未发生，要求重发。

调度工具用 FastMCP 实现，带完整测试。

## 收获

**想让 hook 管住什么，就必须让它出现在工具参数里。**提示词里的规则是建议，参数上的约束才是保证。
