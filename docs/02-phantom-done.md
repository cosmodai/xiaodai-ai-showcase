# 复盘 02：假完成，以及为什么要让机器来判定完成

## 现象

在小戴的失败模式里，“假完成”排第二：agent 宣布任务完成，但实际效果没有发生。典型例子：

- 活动配置保存成功，但商品下架，顾客侧看不到活动价
- 看板本地刷新了，共享页面还是旧版本
- 消息“已发送”，对方没收到
- 报告生成了，用的却是过期缓存

这类问题很难发现，因为执行日志里每一步都显示成功。

## 根因

完成与否由执行者自己报告。agent 汇报的是“我做了某个动作”，而用户关心的是“世界的状态变了”。这两者之间的差距，自我汇报覆盖不了。

另一个相关现象：当模型对某类任务很有把握时，会跳过技能模板，直接凭参数记忆生成。结果格式像模像样，内容却不符合要求，而它照样报告完成。

## 修法

1. **每类任务定义可机器检查的完成断言。**比如周报要检查数据截止日，活动要在顾客侧回读价格，看板要比对接收方看到的版本号。
2. **agent 的“完成”只是申请。**断言通过才进入下一步；失败就带着失败原因退回。
3. **外发统一经过发件箱。**每次投递带任务编号，收到同编号的回执才归档。投递失败可以按编号补发，不会重复也不会丢。

## 收获

**完成的定义应该写在系统里，而不是交给执行者判断。**这也是作品集里 11、13、15、16 四个案例共同的思路。
